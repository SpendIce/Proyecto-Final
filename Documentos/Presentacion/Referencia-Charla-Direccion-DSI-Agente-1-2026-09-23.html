3 · Accesos: qué pedirle a Fernando Vera / DSI DEF-A1-001/002/003 · BLOQUEADO_EXTERNO

Documento madre (ya en sus manos desde el 22/07): Especificacion-Tecnica-Entornos-Pruebas-Preproduccion-Agente-1.md · nota operativa del 19/08. Objetivo: provisionar D2 — Sandbox Workspace para destrabar el camino a G2.

La decisión que ordena todo lo demás — identidad técnica (§3)

  • Alternativa A: cuenta dedicada @fie.undef.edu.ar con consentimiento OAuth (refresh token, custodia, dependencia de una identidad).
  • Alternativa B: service account administrada por el DSI sobre Shared Drive (sin dependencia de persona; exige cambio técnico: hoy documents.create no resuelve Shared Drive/carpeta → implementar flujo Drive + prueba de integración).
  • Aclaración a llevar: una dirección de email no autentica llamadas a APIs — toda llamada privada lleva OAuth 2.0 por debajo, incluso con service account. Con el mail solo hay identidad; falta proyecto Cloud, consent screen, Client ID y custodia del refresh token.

Pedidos concretos

  • Proyecto Google Cloud para D2 — preferentemente exclusivo (compartido solo con aislamiento documentado). APIs: Sheets v4 + Docs v1 obligatorias; Drive v3 condicional (Shared Drive/carpeta/plantilla); Gmail fuera de alcance.
  • Si va Alternativa A: pantalla de consentimiento tipo Internal para fie.undef.edu.ar (evita verificación de Google y la expiración de 7 días del refresh token en modo Testing) + OAuth Client ID tipo Desktop + la cuenta hace el consent flow una vez. Definir quién custodia el refresh token.
  • Recursos D2 exclusivos: planilla, plantilla y carpeta de pruebas, sin contenido real (la plantilla/carpeta puede venir de la SEU; el DSI coordina permisos).
  • Administrador DSI designado — titular + suplente, dueño operativo de proyectos, identidades, secretos, permisos y revocación.
  • Scopes a validar por DSI: spreadsheets.readonly (lectura) y drive.file (candidato para crear docs); evitar scopes amplios.
  • Host para Ollama: referencia PoC = x86_64 4c/8h, ~16 GiB RAM, CPU. Volumen SEU: 36 generaciones/mes ≈ 12 min de cómputo. Dato nuevo: llama3.1:8b da 4/6 en conformidad (vs 1/6 del 3B) pero con 40–160 s por generación en CPU — si se adopta el 8B, el dimensionamiento del host cambia.
  • Egress: HTTPS 443 solo a oauth2.googleapis.com, sheets, docs (+ www.googleapis.com si Drive). Sin ingress ni endpoint público; Ollama no se expone a la red.
  • Retención: logs, borradores, backups y manifests — plazo, custodia y eliminación pendientes de definición DSI + SEU.
Controles ya comprometidos de mi lado (para mostrar que el pedido es serio): identidad distinta por ambiente · propietario nominal + suplente · acceso solo a archivos autorizados · sin domain-wide delegation · sin API keys para datos privados · sin archivos públicos ni «cualquiera con el enlace» · sin contraseña institucional como credencial · secretos fuera del repo, logs y evidencias. No pido ni recibo contraseñas ni claves por correo.

Entregables que debería producir la coordinación (§17)

1) decisión de identidad + diagrama de acceso · 2) proyectos y APIs por ambiente · 3) inventario de recursos con IDs por canal seguro · 4) matriz de scopes efectivos · 5) procedimiento de alta/rotación/revocación · 6) baseline del host + prueba de conectividad · 7) acta de smoke técnico · 8) pendientes y condiciones de avance a D3.
